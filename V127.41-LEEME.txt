NIÑOS RANCIOS — V127.41 SEGURIDAD / PREPRODUCCIÓN
Fecha: 2026-10-02
Base: V127.40 — Catálogo personalizable

OBJETIVO
Primera fase de endurecimiento de seguridad antes de publicar la tienda en un hosting real.
No se modificó intencionalmente el diseño de la tienda ni el flujo visual ya validado.

CORRECCIONES PRINCIPALES
1. Se eliminó la publicación estática de toda la raíz del proyecto.
   - /server y /server/* quedan bloqueados con 404.
   - Solo se sirven como estáticos /assets, /icons y los archivos públicos HTML/CSS/JS de la raíz.
   - admin.html continúa protegido por su ruta administrativa.

2. Cabeceras de seguridad.
   - Helmet agregado.
   - X-Powered-By desactivado.
   - X-Content-Type-Options, Referrer-Policy y otras cabeceras provistas por Helmet.
   - Permissions-Policy agregada.
   - HSTS se activa únicamente con NODE_ENV=production.
   - CSP estricta queda pendiente porque el frontend actual todavía contiene scripts inline y proveedores de pago externos.

3. IP y proxy.
   - El servidor ya no confía manualmente en X-Forwarded-For.
   - Se usa req.ip con trust proxy configurable mediante TRUST_PROXY_HOPS.
   - En localhost, TRUST_PROXY_HOPS=0 / NODE_ENV=development.

4. Rate limiting adicional.
   Se limitaron registro, evaluación de promociones, creación/finalización de pagos,
   pedidos por transferencia/contraentrega, carga de comprobantes y consulta pública de pedidos.

5. Inventario en transferencia y contraentrega.
   - Transferencias pendientes vencidas devuelven inventario automáticamente.
   - Contraentrega reserva inventario por 48 horas por defecto mientras siga en estado Nuevo.
   - Si una contraentrega pendiente se cancela manualmente, devuelve el inventario.
   - Si se sube comprobante de transferencia, se concede una ventana de revisión antes de liberar stock.
   Variables: COD_RESERVATION_HOURS y BANK_PROOF_REVIEW_HOURS.

6. Abuso de pedidos manuales.
   - Máximo de pedidos manuales activos/no pagados por correo o teléfono dentro de una ventana de 24 horas.
   - Los cupones de transferencia ya no consumen uso hasta marcar el pago como pagado.
   - Los cupones de contraentrega se contabilizan al marcar el pedido como Entregado/Pagado.

7. Escrituras críticas más seguras.
   - Escrituras de pedidos/inventario/payment drafts usan archivo temporal + rename para reducir riesgo de archivos parcialmente escritos.

8. Protección frente a doble finalización de pagos dentro de un mismo proceso Node.
   - Stripe, PayPal y Mercado Pago usan un bloqueo temporal por identificador de pago durante la finalización.
   IMPORTANTE: esto protege un solo proceso. Para varias instancias sigue siendo necesaria una base de datos con restricciones UNIQUE/transacciones.

9. Dependencias de seguridad preparadas para actualización.
   - express ^4.22.3
   - multer ^2.4.0
   - nodemailer ^10.0.13
   - helmet ^8.3.0
   - Node >=20

10. Se agregó .gitignore para evitar subir secretos y datos privados generados.

11. Se agregó:
    npm run security:check
   que ejecuta server/security-smoke-test.js y comprueba, entre otras cosas, que /server/data/orders.json y /server/server.js no sean públicos.

ANTES DE PROBAR ESTA VERSIÓN
Desde la carpeta server ejecutar:

  npm install
  npm run security:check
  npm start

IMPORTANTE
En el entorno donde se generó este ZIP no fue posible completar npm install, por lo que las comprobaciones realizadas aquí fueron de sintaxis y lógica aislada. Después de instalar dependencias en tu PC se debe ejecutar el security smoke test.

ESTADO
Esta versión es PREPRODUCCIÓN. Todavía NO se recomienda activar pagos reales en Wasmer.
Siguiente fase recomendada: mover pedidos, clientes, sesiones, inventario, promociones y control de pagos desde archivos JSON a una base de datos persistente con transacciones e índices únicos. También queda pendiente una CSP estricta y, opcionalmente, MFA/usuarios administrativos separados.
